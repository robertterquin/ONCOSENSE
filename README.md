# OncoSense

A cancer awareness and support app: cancer information, self-check guides and healthy habits, a Q&A forum, support resources, a personal journey tracker, and health reminders.

Built with **React Native (Expo)** and **Supabase**. The original Flutter app was retired in October 2026; see [Flutter archive](#flutter-archive).

## Repository layout

| Path | What's there |
|---|---|
| `src/` | The app (Expo, TypeScript, Expo Router). Every file in `src/app/` is a screen. |
| `assets/`, `scripts/` | App images and fonts, and the scripts that generate icons |
| `supabase/` | Database migrations, the `delete-account` Edge Function and the Supabase CLI config |
| `supabase/reference/` | The original setup SQL and notes for the bookmark, journey and cancer-type tables (the rest of the schema lives only in the Supabase project) |
| `docs/` | The redesign, the design refresh, the Flutter migration, and the [release checklist](docs/release-checklist.md) |
| `.maestro/` | End-to-end test flows |
| `.github/workflows/mobile.yml` | CI: lint, typecheck and tests on every pull request and push to `main` |

## Setup

1. Install Node.js LTS.
2. Install dependencies and add the Supabase settings:
   ```bash
   npm install
   cp .env.example .env
   ```
3. Fill in `.env` with the Supabase project URL and **anon** key (Supabase dashboard → Project Settings → API).

## Run

| Command | What it does |
|---|---|
| `npm start` | Start the dev server (open in a development build) |
| `npm run ios` / `npm run android` | Build and run a development build locally (needs Xcode / Android Studio). If `pod install` fails with an encoding error, run `export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8` first |
| `npm run web` | Run in the browser |

## Check

| Command | What it does |
|---|---|
| `npm run lint` | ESLint |
| `npm run typecheck` | TypeScript |
| `npm test` | Jest unit tests |
| `npm run format` | Prettier |
| `npx expo-doctor` | Check dependency and config issues |

Add native packages with `npx expo install <package>` so versions match the Expo SDK.

`ios/` and `android/` are generated by `npx expo run:*` / `npx expo prebuild` and are not committed. Change native settings in `app.json` (and config plugins) instead.

## End-to-end tests (Maestro)

Install [Maestro](https://docs.maestro.dev), start a development build on a simulator or emulator, then:

```bash
maestro test .maestro/guest-tour.yaml
```

The signed-in flow needs a throwaway test account (never a real user's):

```bash
maestro test -e EMAIL=test@example.com -e PASSWORD='…' .maestro/signed-in.yaml
```

## Supabase

The app uses the existing Supabase project (auth, Postgres with Row Level Security, the `images` storage bucket). One Edge Function lives in `supabase/functions/` and needs to be deployed with the [Supabase CLI](https://supabase.com/docs/guides/cli):

```bash
supabase link --project-ref <project-ref>
supabase functions deploy delete-account
```

- `delete-account` deletes the signed-in user's data and account (required by the app stores).

## Release builds (EAS)

Each profile in `eas.json` reads its variables from the EAS environment of the same name, so the Supabase values never go in git. Set them once per environment (the anon key is public by design; Row Level Security protects the data):

```bash
npx eas-cli@latest env:set --name EXPO_PUBLIC_SUPABASE_URL --value https://<project>.supabase.co --environment production --visibility plaintext
npx eas-cli@latest env:set --name EXPO_PUBLIC_SUPABASE_ANON_KEY --value <anon key> --environment production --visibility sensitive
```

Repeat for `preview` and `development`. Then build with `npx eas-cli@latest build --profile production --platform all`. What's left before a store release is in the [release checklist](docs/release-checklist.md).
